# 专家团 vs DSH 内置智能体团队（Agent Teams）

这两个能力**不互相替代**，也不共用任何状态：

- **Agent Teams（内置）**：把任务拆给若干**真实子代理**，每个子代理有自己的会话、工具与工作区；适合"派活执行"——并行调研、改代码、跑测试、跨文件落地。
- **专家团（本插件）**：把一次**专业判断**拆给若干**专家镜头**，Host 为每位专家各发一次独立模型调用，按领域证据标准审查，只对分歧交叉质询，最后主持裁决并留下报告；适合"专业评审与留痕"。

所以本文件回答的是：**在专业评审类任务上，专家团是否不弱于 Agent Teams。** 结论：在下面 6 个专业评审维度上专家团更强；在"需要工具执行与多文件落地"的任务上 Agent Teams 更强。两者可以并用：先用 Agent Teams 收集证据/实现方案，再把结果交给专家团评审。

## 对照矩阵

| 维度 | 专家团（V0.4） | DSH Agent Teams |
| --- | --- | --- |
| 独立性 | Host 直接调用模型 N 次，每位专家只看到自己的镜头 prompt，看不到其他人的回答 | 每个 teammate 是独立会话，独立性更强（有独立上下文与工具） |
| 领域专业性 | 6 个专业领域包：A–E 证据阶梯、必须核验项、红旗、交付物清单进入 system prompt 与报告核对表 | 通用代理，无领域证据标准（需用户自行写 prompt） |
| 分歧处理 | 自动检测立场/置信度分歧，只对分歧做交叉质询；主持必须回应并在存在分歧时写 dissent | 无内置分歧检测；依赖 Lead 自行比较 |
| 裁决与异议 | 强制结构：decision/confidence/rationale/dissent/unresolved/reversalTriggers/actions；忽略分歧会被重写 | 无固定裁决结构；由 Lead 自由总结 |
| 留痕与复查 | 台账 + 完整运行转录 JSON + 8 节 Markdown 报告落盘；可 `run_status` / `report` / `cancel_run` | 会话日志 + 任务板；无统一的专业评审报告格式 |
| 成本与可预期性 | 固定调用数（N 专家 + ≤4 交叉质询 + 1 主持），token/耗时先估算后实测，超预算告警 | 子代理自主决定步数/工具调用，成本与时长波动更大 |
| 工具执行 | 无工具调用，只做判断 | 有完整工具与工作区，可执行任务 |
| 隔离 | 独立命名空间，不创建代理、不碰 Agent Teams 状态 | 内置能力，自身即代理编排 |

## 专业评审评分（5 维，满分 5）

维度：① 领域证据标准 ② 独立成稿 ③ 强制异议 ④ 可复查报告 ⑤ 成本可预期。

| 方案 | ① | ② | ③ | ④ | ⑤ | 总分 |
| --- | --- | --- | --- | --- | --- | --- |
| 专家团 standard（真实运行） | 5 | 5 | 5 | 5 | 4 | **24/25** |
| Agent Teams（Lead + 3 teammates，同模型） | 2（需自写领域标准） | 5 | 2（无强制结构） | 3（有会话日志，无统一报告） | 2（步数不固定） | 14/25 |

说明：② 双方都给 5，因为 Agent Teams 的子代理确实有独立会话；本插件用"每次调用独立、互不可见"达到同一目的，成本更低。⑤ 专家团扣 1 分，因为推理模型的思考 token 会让实际用量高于预算估算（V0.4 已把该差异写入告警与报告）。

## 真实运行证据（金融领域，同一问题）

- 问题：某中型制造企业 3 亿元闲置资金投结构化票据（挂钩海外高收益债，2 年，目标年化 7%，回撤容忍 8%）是否批准。
- 运行：`standard`，deepseek-account/deepseek-flash，桌面运行时。
- 规模：5 位专家并行独立成稿（5/5 成功）→ 检测到 3 处分歧 → 4 路交叉质询并写回第 2 轮修订 → 1 次主持裁决；共 9 次模型调用。
- 结果：45.5s、16,857 token；裁决「不做（当前材料下不予批准，非永久否决）」置信度 0.8；1 条异议（合规官 conditional 被其余四席反对）、4 项未决、3 条推翻条件、1 组分工到人的行动项；8 节报告落盘（含逐专家调用明细）。
- 报告路径：`$DSH_HOME/expert-council/runs/run-20261107-015315-810b-mw59w89k.md`。

## 任务会诊：边界为零的实证

同一套研究领域团队（领域专家/方法学/伦理 IRB/可复现/期刊编辑），在 `intent=task` 下被要求写一篇 800 字赛博朋克短篇小说：

- 4/5 位专家交付了完整短篇（第 5 位伦理专家产出不符合契约被记为失败，任务模式允许降级继续）；
- 总集成者把 4 个版本合并成一篇约 950 字的《离线病人》，保留各自最强部分（身体意象、方法学张力、离线档案意象、双向道德反转）；
- 71.6s、36,142 token；报告含最终成果、分工表、各专家交付物、假设/风险、未决与下一步；
- 没有任何“这超出科研领域”的拒答或降权；领域包只作为镜头基线。

这说明“没有任务边界”不是文案：同一批专家既能评审投资决策，也能写小说、出方案、做攻击面分析。任务会诊与 Agent Teams 的差别仍然是：专家团不做工具执行，但产出是结构化的多专家合并稿；需要动手落地时仍建议配合 Agent Teams。

## 什么时候用哪个

- 需要**动手执行**（改代码、跑测试、查资料、跨文件落地）→ Agent Teams。
- 需要**专业判断 + 证据标准 + 异议留痕 + 可归档报告**（投委会、合规评审、论文评审、设计评审、事故复盘）→ 专家团。
- 需要"先执行再评审"→ 两者串联：Agent Teams 产出材料，专家团评审材料。
